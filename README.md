# muti-monitor

Binance 多标的行情与技术分析网页，支持：

- XAUUSDT、SNDKUSDT、SKHYNIXUSDT 切换
- H4 / H1 / M15 使用真实已收盘K线动态执行 SMC 多周期分析，不使用写死点位或演示信号
- 成交密集区只负责确定支撑压力位置，历史反应和实时订单簿只调整可信度，多周期重合不再重复加分
- H4 由 EMA200 与同向 BOS 建立主方向，之后持续有效，直到反向 CHoCH 或价格穿越 EMA200；RSI、MACD只作动能展示
- H1 以成交密集区为核心生成主执行区；存在更靠近现价的有效结构区时，同时提供临近次级执行区；EMA20 / EMA50只作展示
- M15 支持两条入场路径：“进入执行区 → 扫流动性 → 同向CHoCH”，或“执行区拒绝K线 → 微型结构突破”；盈亏比只作风险展示
- 支撑压力区域地图展示H4外部流动性、H1主/次执行区与当前价；入场清单实时显示四层条件完成度
- 止损放在执行区和扫单极值之外，TP1/TP2/TP3分别参考邻近结构区、下一结构区与H4外部流动性；盈亏比仅作风险展示
- 5分钟、15分钟、1小时、4小时和日线周期，5日至全部时间范围
- MA20 亮蓝色、MA60 琥珀橙色显示及独立开关
- K 线、RSI 联动悬停和可视时间轴
- K线悬浮信息框会自动远离鼠标并在图表边缘智能换边
- 主K线图以当前视图最右侧K线为锚点进行滚轮缩放，不受鼠标所在位置影响
- 主K线图支持按住鼠标左键左右拖动可视区间
- 在最新行情处向左拖动可保留最多约22%的右侧未来空白，K线与RSI保持比例并在绘图区边界自动裁切
- 滚轮设定可见K线大小后，切换K线周期、时间范围或扩展历史数据会保持可见根数与K线宽度，并自动锚定最新行情；纵向价格边界继续自动适配
- 滚轮继续向外缩放或拖动触及历史边界时，会按 5日→1月→3月→6月→1年→全部 自动扩展数据范围
- 主K线图桌面高度为 710px、手机高度为 642px（在上一版基础上再加高50%）
- 宽屏与手机端的图表坐标文字会自动校正比例，避免字体被横向拉伸或压扁
- 浏览器 IndexedDB K 线缓存
- 支撑压力以30日5分钟K线成交量分布为长期基础，识别 POC、VAH、VAL 与 HVN；历史触碰、价格反应和多周期重合负责确认
- 实时接入20档订单簿深度，只有持续挂单墙、撤单与买卖盘失衡会对邻近区域作有限加减分，深度不会单独生成支撑压力
- 不请求聚合成交明细；历史K线与成交量分布优先读取当前浏览器缓存，之后只增量同步末尾数据；成交分布暂不可用时只降低支撑压力增强项，不影响SMC结构继续计算
- 不请求仅用于展示的24小时Ticker接口；24小时涨跌、高低点与成交量复用支撑压力已取得的5分钟K线在浏览器本地计算
- H4主趋势生成SMC顺势主策略；H1反向供应/需求区只有在M15形成反向CHoCH后才生成备选逆势方案，两种策略均可独立锁定

## Cloudflare Workers 部署

本项目使用一个轻量 Worker 做密码校验，并通过 Workers Static Assets 提供网页，不需要构建步骤。

- Worker 名称：`muti-monitor`
- 生产分支：`main`
- Build command：留空
- Deploy command：`npx wrangler deploy`
- Root directory：留空（使用仓库根目录）

`wrangler.jsonc` 会让所有请求先进入 `src/worker.js` 完成密码校验，再从 `public/` 提供静态资源。

## 隐私

仓库中不包含 GitHub 部署私钥、Cloudflare 凭据、访问密码或账户信息。Worker 采用 HTTP Basic Authentication，并对所有静态资源强制校验。

在 Cloudflare Worker 的 `Settings` > `Variables and Secrets` 中添加：

- Type：`Secret`
- Name：`ACCESS_PASSWORD`
- Value：自行设置至少 12 个字符的强密码

默认用户名是 `monitor`。如需修改，可以另加一个文本变量 `ACCESS_USERNAME`。密码未配置或少于 12 个字符时，Worker 会返回 `503`，不会公开网页。

请勿将真实密码写入 `wrangler.jsonc`、GitHub 仓库、构建变量或聊天消息。

## 数据来源

网页优先从访问者浏览器调用 Binance Futures 公开 REST 与 WebSocket 接口，浏览器直连受限时自动回退到同源 Worker 代理。K线和成交量分布缓存只保存在当前浏览器的 IndexedDB 中，不会提交到 GitHub；定时刷新只同步最近几根K线，不会重复下载整个历史区间。
